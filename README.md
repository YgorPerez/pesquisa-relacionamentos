# Pesquisa: relacionamentos, apps de namoro e onde conhecer pessoas

![fallow health](docs/badges/fallow.svg) ![react doctor](docs/badges/react-doctor.svg) ![cobertura](docs/badges/coverage.svg)

Documentação pessoal de estudos sobre como casais se conhecem, a qualidade e a duração dessas relações e o que funciona para conhecer alguém, com foco em um homem de 21 anos no Brasil.

A regra é simples: **cada afirmação aponta para a fonte primária que a sustenta**, e cada estudo diz até que ponto foi conferido.

## Estrutura

| Pasta/arquivo                      | O que tem                                                                                                                                                                |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| [`studies/`](studies/)             | Uma ficha por estudo ou fonte: o que mediu, números principais, limitações e status de verificação                                                                       |
| [`reports/`](reports/)             | Sínteses que cruzam vários estudos para responder a uma pergunta, com o `ticket:` que as pediu no topo                                                                   |
| [`tips/`](tips/)                   | Conclusões práticas, cada uma ligada aos estudos que a sustentam                                                                                                         |
| [`sources/`](sources/)             | Fontes locais de licença aberta ou domínio público, com a licença registrada na Ficha. O resto vai para `sources/private/`, clone de um repo privado e fora do git deste |
| [`docs/deploy.md`](docs/deploy.md) | Como o site vai ao ar em temestudo.cloud e como voltar à versão anterior                                                                                                 |

O que falta verificar ou pesquisar está nas [issues com o label `acervo`](https://github.com/YgorPerez/pesquisa-relacionamentos/issues?q=is%3Aissue+is%3Aopen+label%3Aacervo). O passo a passo para trabalhar uma delas está na skill [`library`](.claude/skills/library/SKILL.md).

## Convenções

**Status de verificação** (campo `status` no frontmatter de cada ficha: `verified`, `partial` ou `unverified`):

- ✅ **Lido no original:** números conferidos no texto completo do artigo/relatório.
- 🟡 **Parcial:** conferido no resumo, página oficial ou comunicado, mas não no texto completo.
- ⬜ **Não verificado:** citado de memória ou por fonte secundária; precisa ser conferido antes de usar.

**Força da evidência:**

- **Forte:** amostra grande e representativa, replicado, ou meta-análise.
- **Moderada:** bom desenho, mas uma única amostra, transversal ou com algum viés conhecido.
- **Fraca:** amostra pequena, não representativa, comercial ou com conflito de interesse relevante.

**Nomes de arquivo:** `studies/<sobrenome-primeiro-autor>-<ano>-<tema-curto>.md`. Relatórios: `reports/<AAAA-MM-DD>-<tema>.md`. Fonte local: `sources/<slug-da-ficha>.<pdf|html|txt>` ou `sources/private/<slug-da-ficha>.<pdf|html|txt>`.

Para uma ficha nova, copie [`studies/_modelo.md`](studies/_modelo.md). Os campos do cabeçalho ficam no frontmatter YAML, e o build do site (`packages/content`) falha com a lista de erros quando um campo é inválido, sai de uma lista fechada ou repete o DOI de outra ficha.
